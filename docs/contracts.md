# Public contracts (A05)

A05 defines the v1 knowledge contract and separately versioned v1 browser contract. These are validation/type definitions, not functioning tools. The feasibility server still advertises no product tools. Tool implementations, graph/reference checks, redaction and live browser enforcement remain assigned to later tasks. The baseline is [v0.2](specification-v0.2.md), with only [ADR-001](decisions/001-bundled-browser.md) and the plan's amendments.

The source of truth is `src/contracts/`: common envelopes/primitives/limits, capture/view structure, commit operations, record summaries, knowledge tools and browser tools. `z.strictObject` rejects unknown fields at every fixed object boundary. TypeScript request/response types and JSON Schema come from those same Zod definitions. `npm run build` emits executable ESM, declarations and `dist/contracts/schemas.json`. Consumers can import `waygrain/contracts` or `waygrain/contracts/schemas.json`; `contractJsonSchemas()` returns fresh generated schemas. No separately hand-maintained schema copy is committed.

```ts
import {
  validateRequest,
  validateResponse,
  ContractError,
} from 'waygrain/contracts';
// Validation has no browser, store or network effects.
// Callers must redact and enforce configured scope before ingestion/persistence.
```

Knowledge requests carry `schema_version: 1`, project/app UUIDs; writes also carry a bounded opaque `request_id`. Browser requests additionally require `browser_schema_version: 1`; open, navigate, act and close carry request IDs. Navigate/act also carry an `execution_id`, separate from graph idempotency. Durable identities are UUIDs. External trace/session/tab provenance and caller keys use bounded opaque strings. Scope has environment, exact HTTP(S) origin, role, account alias and locale; an omitted role becomes `unknown`, never a wildcard. Caller scope membership/identity matching requires the later configured services.

Success envelopes carry `schema_version`, `store_revision`, typed `data`, structured `warnings` (`code`, `message`, `affected_ids`) and optional `next_cursor`. Browser envelopes also carry their browser version. Cursors contain an opaque token and store revision; the later query service must bind the token to filters and refuse stale revisions. Parsing a cursor does not verify its authority. The commit receipt contains created IDs, client-reference mappings and new revision; later atomic services must ensure receipt revision matches the envelope.

## Knowledge tools

| Tool              | Request                                                                                                | Typed result                                                                                                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `wg_status`       | Project/app envelope                                                                                   | Store/schema versions, declared knowledge capabilities, counts, database/WAL/cap bytes, supported ingest formats                                                                   |
| `wg_ingest`       | Write envelope, explicit existing/new screen reference, structured capture, optional expected revision | Complete capture: state ID/hash, null fragment hash; partial: null state ID/hash, fragment hash and no state-owned controls; both include screen/capture IDs and redaction summary |
| `wg_commit`       | Write envelope, expected revision, 1–100 typed operations                                              | Created IDs, local client-reference mappings, new revision                                                                                                                         |
| `wg_query`        | Tagged search/neighbors/path/flow input, scope, filters or IDs, budget, cursor, max age                | Typed record summaries with evidence/provenance/coverage/freshness; explicit complete, no-matches or incomplete status and conditional/needs-check applicability                   |
| `wg_evidence`     | Explicit capture/annotation IDs, projection (default summary), budget/cursor                           | Available summary or structured redacted evidence; unavailable and incomplete are distinct                                                                                         |
| `wg_changes`      | Capture pair or scoped revision range, budget/cursor                                                   | Comparable structural/annotation changes with coverage, evidence and invalidated IDs, or explicit incomparable reason                                                              |
| `wg_plan_refresh` | Target IDs, required scope, max age, step budget                                                       | Declarative minimum observations/prerequisites; planned, blocked, unsupported or needs-user-input status; no executable action                                                     |

A capture includes captured time, trace ID/sequence, session/tab aliases, source producer/format versions, scope, view (route template, ordered tabs/modals/variants), accessibility-style tree, complete/partial coverage and versioned redaction profile. Tree nodes contain role, safe name, enabled/visible/optional selected flags, ordered children and an optional descriptive accessible-name/test-ID hint with source/time. Unknown raw fields, input values, transient node references, cookies and screenshots have no schema slot. Approved text still needs B02 redaction and operator label review: syntactic validation is not privacy certification. Locator hints remain descriptive evidence, never live handles.

Commit variants are create action, record action event, record test run, create transition, create flow, add annotation, supersede annotation and explicit identity alias. Existing references and request-local client references are distinct tagged objects. The parser rejects duplicate declared client references, reversed test-run times and test-verified transitions without a test-run reference. An inferred annotation requires a rationale; a test-verified annotation requires a test-run reference. Action schemas describe possible input types without storing values. Safe action-event error codes are enumerated. Events may have null after-capture IDs, but transitions require complete before/after IDs and an action-event link. Inferred transitions cannot be created by the transition operation. The typed relation endpoint table is exported; there is no arbitrary create-edge operation.

Record summaries retain the ten record kinds' structural identity fields and evidence/freshness metadata. Transition summaries include source/action/target and trace-evidence references. Flow transition IDs retain order. Query results must be ordered by the later service according to search ranking or path/flow order; schemas do not compute traversal. Structured capture evidence includes its stored request ID and receipt time. Structured annotation evidence retains kind, author, revision, supersession and provenance-specific rationale or test-run ID. Annotation semantic claims remain separate from observed structure.

## Browser tools

| Tool                  | Request                                                                             | Typed result                                                                      |
| --------------------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `wg_browser_open`     | Versioned write envelope and scope                                                  | Owned ephemeral headed page/session and explicit capabilities                     |
| `wg_browser_snapshot` | Session/page IDs                                                                    | Current snapshot ID, sanitized ingest-compatible capture and ephemeral target IDs |
| `wg_browser_navigate` | Request/execution IDs, current session/page/snapshot binding, scope and HTTP(S) URL | Sanitized attempt receipt                                                         |
| `wg_browser_act`      | Request/execution IDs and tagged bounded action with current binding/target         | Sanitized attempt receipt                                                         |
| `wg_browser_status`   | Optional session/execution filter                                                   | Open/closed state, capabilities and bounded attempt receipts                      |
| `wg_browser_close`    | Request ID and session ID                                                           | Closed state and complete/unconfirmed cleanup result                              |

Capabilities explicitly declare `ephemeral_owned`, headed operation and no persistent authentication. Temporary action targets bind to session/page/snapshot UUIDs. Selection refers to an ephemeral option UUID from the current snapshot, rather than a stored option value. Actions are click, ephemeral noncredential fill, select, check/uncheck, bounded scroll and navigation keys. The key allowlist is Tab, Shift+Tab, ArrowUp, ArrowDown and Escape; selectors, JavaScript, shell commands, uploads/downloads and dialog acceptance have no schema slot. Fill text exists only in the transient request; receipts/attempt markers never contain it. Fixtures retain no nonempty fill input value. Actual credential-field refusal and target freshness/ambiguity checks remain C03/C04.

Navigation URL syntax rejects query, fragment, userinfo and non-HTTP(S) schemes. It is transient input only; outputs retain the sanitized capture route template. Navigation still requires C03 allowlisted-origin/redirect enforcement. Schema-valid URLs and actions grant no permission. Manual login, consequential application actions and scope changes remain governed by the user/host.

An attempt contains execution ID, live binding, target ID (nullable for navigation), trace/sequence, action kind, occurrence time, optional after-snapshot ID and safe error code. States distinguish `not_started` (never dispatched), `pending`, `succeeded`, `failed` (dispatch occurred) and `unknown` (dispatch occurred or is uncertain). An unknown result requires `UNKNOWN_OUTCOME`; it cannot claim no dispatch. A successful receipt requires dispatch and no error. Pre-dispatch rejection has no after-snapshot. Application effects are not a graph transaction: a failed/unknown action does not claim rollback. C04 must persist sanitized pre-dispatch markers and refuse replay of every execution ID, including uncertain interrupted attempts. A schema cannot prove that behavior.

## Bounds and errors

The contract parser enforces 1 MiB maximum serialized request size (the baseline ingest ceiling, also a defensive boundary for other tool requests), 5,000 total tree nodes, root-counted depth 64, 4 KiB UTF-8 per string, and 100 commit operations. It checks JSON shape/cycles/accessors before recursive Zod parsing. Capture future timestamps allow five minutes; older imported captures remain historical. Tree bounds also apply to structured evidence responses; capture evidence and summaries enforce null state identity for partial coverage. The parser never truncates to make invalid input pass. Error paths are bounded metadata and are capped to their envelope limit. Query defaults are 20 records and 8 KiB, maximum 50 records; caller byte budgets may be larger. Neighbor default is one hop/max three; path default/max depth eight and 500 visited nodes; max-age default is 24 hours. Service output byte accounting, pagination and scope/reference checks remain later behavior.

`validateRequest`/`validateResponse` throw a `ContractError` whose `toJSON()` emits only version, stable code, a fixed message and schema-owned field paths. Caller-supplied unknown property names and rejected values are excluded. Structural ceilings report `LIMIT_EXCEEDED`; malformed input uses `INVALID_INPUT`; unsupported contract versions use `UNSUPPORTED_SCHEMA`. The shared error schema also covers the baseline's scope, format, storage, revision, idempotency, budget and cursor codes plus separately versioned browser refusal/uncertainty codes. The A03 configuration and A04 process codes remain separate.

Generated JSON Schema enforces structural types, fixed-object strictness, enum variants, lengths and array/numeric limits. Total tree count/depth, UTF-8 byte size, serialized size, temporal context, unique local references and refinement rules need the parser; they are not silently claimed as JSON Schema features. Likewise, services must enforce same-scope/session/tab/trace identity, monotonic sequence and timestamps, complete transition endpoints, passed matching assertions, revision guards, sanitized idempotency, cursor binding, redaction and origin/live-target authority. A05 contract tests do not verify those services.

`npm run check` includes synthetic fixtures for all 13 request/response pairs in both Zod and the SDK's independent AJV JSON Schema validator, strict unknown-field rejection, mode/operation/action/attempt variants, limits, errors, partial captures and generated-artifact equality. The [test fixtures](../tests/fixtures/contracts.mjs) describe schema examples, never runtime product evidence. Zod API basis: [strict objects and recursive schemas](https://zod.dev/api), [JSON Schema generation](https://zod.dev/json-schema).

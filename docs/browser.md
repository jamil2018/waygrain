# Bundled browser lifecycle

C01 implements `wg_browser_open`, `wg_browser_status` and `wg_browser_close` through the stdio endpoint. The strict A05 contract requires the configured project/application IDs and `browser_schema_version: 1`. Opening requires a complete configured scope and an opaque request ID. It starts one headed Chromium window at `about:blank`; installation remains explicit (`waygrain install-browser`). A repeated open ID returns the same current session, and never resurrects a closed session. A different open while one is owned fails with `CONFLICT`.

A human may use the headed window to navigate to that scope's origin and log in. The context is nonpersistent; Waygrain never requests, reads, outputs or saves input values or authentication state. The synthetic login harness simulates form entry, tests a successful same-origin login, and checks that reopening has no session cookie. Real-account, MFA and coding-host compatibility are unverified. Federated/cross-origin login and WebSockets are currently unsupported. Scope aliases describe operator-declared context, not proof of a user's role or backend permission.

The isolated worker uses an owner-created private temporary root. It launches Chromium with its default temporary profile, a nonpersistent context, blocked service workers and downloads, and no recording. HTTP(S) routing permits only the selected scope origin; other requests are aborted. Extra pages are closed and dialogs dismissed. Raw URLs, request bodies, page content, browser diagnostics and authentication state never cross IPC. Status has no page content or URL; implemented action/key capabilities are empty. Snapshots, navigation and actions remain C02–C04.

Normal close, stdio EOF, signal shutdown and IPC parent loss request cleanup through the live owned worker. Cleanup waits for an in-flight launch before closing the browser and deleting its private temporary root. Close reports `complete` only after successful worker cleanup; timeout/abnormal exit is `unconfirmed` and cannot authorize PID-based cleanup or a second session. Persisted PIDs are never used. A killed worker, simultaneous owner/worker loss, OS failure or hostile filesystem ancestor replacement has no complete-cleanup guarantee; C05 must review failure limits separately.

Run `npm run check` for deterministic checks (no browser install/launch) and `npm run test:browser:lifecycle` for explicit headed lifecycle and synthetic login checks. The process harness covers open/status/replay/conflict/normal-close, SIGTERM and killed-parent cleanup, and verifies scratch-directory removal. It retains no browser artifacts. This local macOS evidence does not attest other operating systems or host integration. Packed lifecycle qualification remains separate from earlier A04/B05 feasibility evidence.

## C02 snapshots

`wg_browser_snapshot` binds the current session/page to a new opaque snapshot. The worker uses public `page.ariaSnapshotJSON`, with raw JSON remaining in worker memory. It emits only configured labels, known roles, bounded ordered structure and safe state; input values, URLs, refs, placeholders and page diagnostics are omitted. A single configured redaction profile is required (ambiguous profiles fail closed). Actual route paths map to exactly one configured template; query/fragment strings never leave the worker. A blank/unmapped or foreign-origin page cannot produce a scoped capture.

Selected tabs and dialogs need separately reviewed lower-case aliases in the profile. Unsupported roles/state flags, unmapped state aliases, password controls or frames yield partial coverage. Unsupported editing hosts (including empty and plaintext-only contenteditable) and input types yield an empty partial projection before reading any raw snapshot; node/depth limits yield truncated partial coverage. `root` is the schema-owned safe subtree descriptor, accepted by ingestion without treating it as page text. All other partial subtree labels retain their allowlist requirement. Partial captures have no state ID. Complete captures cover the supported accessibility projection only, not backend permissions, inaccessible content or every visual property. Targets have random snapshot-local IDs and no permitted actions until C03/C04. The explicit live check is `npm run test:browser:snapshots`; synthetic raw JSON is never retained.

## C03 current targets and navigation

Snapshots cache worker-only element handles. Resolution compares the current sanitized structure with the saved projection, checks session/page/snapshot generation and URL, requires exactly one current role/name match, and compares the matched element with the original handle. Hidden, disabled, replaced, renamed and ambiguous controls fail closed. A new snapshot releases old handles. Target acquisition has a five-second aggregate budget; very large or slow pages can return `LIMIT_EXCEEDED`. Targets remain non-actionable until C04.

`wg_browser_navigate` requires a current snapshot and the exact current configured scope. It permits only mapped HTTP(S) routes on the scope origin, with no query/fragment/userinfo. Navigation invalidates all targets. Chromium request-stage interception checks every redirect hop before egress; ordinary Playwright routing alone cannot enforce that boundary. Same-origin redirects retain their browser URL semantics; foreign-origin hops are blocked. The initial blank window still requires a human to navigate to a mapped route (normally during manual login) before taking the first snapshot; an invented snapshot ID cannot bootstrap agent navigation. Federated origin handoff remains unsupported.

Navigation persists a sanitized pending attempt in the existing private receipt store before worker dispatch. Receipt/request IDs are namespaced; conflicting execution metadata fails, and an existing execution returns its receipt without navigating again. Pending markers found after interruption are unknown and never retried automatically. Only configured route templates, scope and opaque binding metadata enter the digest, never raw URLs, record parameters or input values. Replays with different private route parameters within the same template still never repeat navigation. Status can retrieve one durable attempt by execution ID after browser closure/restart. Marker writes advance the store revision. Successful navigation means the mapped document loaded; it does not certify application behavior or graph writes. Unknown outcomes require human inspection and a new separately authorized execution. `npm run test:browser:navigation` exercises the actual worker driver and durable journal with synthetic pages; it is not coding-host qualification.

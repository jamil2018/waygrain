# Bundled browser lifecycle

C01 implements `wg_browser_open`, `wg_browser_status` and `wg_browser_close` through the stdio endpoint. The strict A05 contract requires the configured project/application IDs and `browser_schema_version: 1`. Opening requires a complete configured scope and an opaque request ID. It starts one headed Chromium window at `about:blank`; installation remains explicit (`waygrain install-browser`). A repeated open ID returns the same current session, and never resurrects a closed session. A different open while one is owned fails with `CONFLICT`.

A human may use the headed window to navigate to that scope's origin and log in. The context is nonpersistent; Waygrain never requests, reads, outputs or saves input values or authentication state. The synthetic login harness simulates form entry, tests a successful same-origin login, and checks that reopening has no session cookie. Real-account, MFA and coding-host compatibility are unverified. Federated/cross-origin login and WebSockets are currently unsupported. Scope aliases describe operator-declared context, not proof of a user's role or backend permission.

The isolated worker uses an owner-created private temporary root. It launches Chromium with its default temporary profile, a nonpersistent context, blocked service workers and downloads, and no recording. HTTP(S) routing permits only the selected scope origin; other requests are aborted. Extra pages are closed and dialogs dismissed. Raw URLs, request bodies, page content, browser diagnostics and authentication state never cross IPC. Status has no page content or URL; implemented action/key capabilities are empty. Snapshots, navigation and actions remain C02–C04.

Normal close, stdio EOF, signal shutdown and IPC parent loss request cleanup through the live owned worker. Cleanup waits for an in-flight launch before closing the browser and deleting its private temporary root. Close reports `complete` only after successful worker cleanup; timeout/abnormal exit is `unconfirmed` and cannot authorize PID-based cleanup or a second session. Persisted PIDs are never used. A killed worker, simultaneous owner/worker loss, OS failure or hostile filesystem ancestor replacement has no complete-cleanup guarantee; C05 must review failure limits separately.

Run `npm run check` for deterministic checks (no browser install/launch) and `npm run test:browser:lifecycle` for explicit headed lifecycle and synthetic login checks. The process harness covers open/status/replay/conflict/normal-close, SIGTERM and killed-parent cleanup, and verifies scratch-directory removal. It retains no browser artifacts. This local macOS evidence does not attest other operating systems or host integration. Packed lifecycle qualification remains separate from earlier A04/B05 feasibility evidence.

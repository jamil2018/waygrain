# Blogen pilot profile

The version 1 [settings fixture](../assets/pilot/blogen-settings.json) targets only the operator's disposable synthetic Blogen at `http://localhost:3000`. It initializes a new private Waygrain store; it contains no credentials or account identifiers. The user authorized all actions against this disposable instance on 8 October 2026. Production Blogen, other origins and repository edits are outside the pilot.

The rules were authored from source in `src/components/studio/AdminCategoriesView.tsx`, `src/components/pages/CategoryListView.tsx` and the corresponding `/admin/categories`, `/categories`, `/login`, `/admin` routes in the separately owned Blogen checkout. No Blogen files are changed. The profile allowlists only category feature labels and a synthetic fixture label; dates, counts, user identity, other record titles and arbitrary page instructions are dropped. Input values never enter captures. The modal also allowlists the derived `create_category` state alias. Scope aliases describe operator-declared synthetic admin/viewer contexts; they do not certify backend roles or permissions.

Run explicit setup using the packed package's [setup guide](../PLUGIN_SETUP.md) and this settings file. Select `local-admin` for the creation journeys and use manual login in the headed nonpersistent browser. Starting at `about:blank` requires manual navigation to a mapped route before the first snapshot. Capture no login page as feature evidence. No cookies, browser profiles or authentication state are saved. Cross-origin login remains unsupported.

The three assigned live journeys are browse/filter public categories, open/cancel category creation, and create one disposable synthetic category. Search uses the public page's explicit `Search categories` accessible label. Creation uses `Create` and `Title` in the admin dialog. Escape may dismiss a dialog when there is no cancel button. Reacquire a snapshot before every action; a stored control is never a handle. Treat a successful driver receipt separately from the application result confirmed by after evidence.

Fixtures test label dropping, route/scope refusal and modal state aliases using invented structured JSON only. They do not establish live Blogen behavior. Unsupported accessibility roles, flags, editing hosts or dev overlays must remain partial coverage. A partial observation has no state ID and cannot support a transition; do not weaken that boundary for the pilot. The live F03 record must identify actual coverage and any unsupported behavior. Actual Codex discovery/new-session recall is F04, Claude Code is deferred F05, and full two-host pilot acceptance remains F06.

# Scoped local clarification history

The conversation service persists only canonical product questions and validated answers. Supported question variants are normalized; unsupported raw text becomes “Unsupported product clarification request.” Raw unsupported text, host inputs, credentials and provider exception messages are not retained. The default provider is the offline synthetic adapter. No answer is reused as source evidence: each turn retrieves current authorized documentation and supplies only an established quantity/price basis for a same-conversation follow-up.

A conversation is bound to trusted principal, project, app, target, page and exact environment/version/role/tenant/state, including null unknowns. History and latest-conversation lookup reauthorize before projecting turns. Forged IDs cannot load another binding. Authorization and principal ownership are checked again after asynchronous generation; changes reject the response before storage. Expected turn numbers serialize replies, and a changed descriptor revision rejects an in-flight answer. Retry from freshly loaded history/evidence after a conflict.

History is append-only and bounded to 20 turns per conversation and 100 conversations per store. At a limit, the request fails explicitly; previous history is retained. A new conversation may be created with a new opaque UUID. Resetting a UI conversation selects a new identity, not delete historical evidence. The next question reestablishes its calculation context. Scope/target switches must discard pending UI responses and clear incompatible view state; component/page panel cleanup discards late UI replies and clears incompatible question/history nodes.

Reload returns only authorized history. Each turn retains its precise descriptor revision and claim/source revision/hash/locator citations. `evidence_current: false` labels an answer from an earlier descriptor revision; it does not update the old answer or make it current evidence. A fresh follow-up uses current sources and warnings, leaving all verification times unchanged. Citations open an inspector that separately authorizes the retained descriptor and source revision; a replacement source is never substituted into a historical answer. The W12 descriptor archive exports knowledge history only; conversation context is deliberately separate and is not included in that format. Whole-store backup/recovery retains both.

Schema migration 6 adds immutable conversation/turn tables without changing descriptor or legacy rows. An existing v5 store receives a private pre-migration backup under exclusive maintenance authority. Migration failure rolls back its DDL; canonical backup/restore validation includes the new schema. Older test downgrade fixtures explicitly remove current conversation tables before constructing their historical test image; historical evidence is unchanged.

On the reader listener, `GET /api/conversation?context=<trusted-key>&target=<id>&page=<id>[&id=<conversation-id>]` returns compatible history (or a new empty identity). `POST /api/ask` takes exactly `context`, `target_id`, `page_id`, `conversation_id`, `expected_turn` and bounded `question`. The exact reader Origin and JSON content type are required. Context keys select preconfigured scopes; body roles/grants are rejected. These routes persist local clarification context only: they grant no host actions or authoring API access. The reusable target adapter still exposes only documentation reads.

Verification: `npm run check`, `node --test tests/descriptor/conversation.test.mjs tests/descriptor/conversation-migration.test.mjs`. Tests cover a separate service-process restart/follow-up, scope/principal/ID forgery, mid-flight source/authorization changes, out-of-order replies, private-file sentinels, history bounds, v5 backup and partial-DDL rollback. The bounded fixture grammar, local single-user trust model and public-release HOLD remain unchanged.

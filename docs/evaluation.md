# Reproducible Codex evaluation

Run `npm run build`, then `node scripts/evaluation/run.mjs /absolute/output.json` with Node 24, the explicitly installed Playwright Chromium, and authenticated Codex CLI on PATH. `WAYGRAIN_CODEX` can select an absolute CLI executable. `--smoke` runs only one cold batch per condition and cannot satisfy G02. Model configuration is explicitly `gpt-6.1-sol`, low reasoning, ignored user config, read-only, fresh ephemeral sessions. This uses existing Codex authentication without reading or saving it. It never edits host settings.

The full matrix contains ten public questions, three repetitions, three conditions and three cases: **270 individual answers in 27 ten-question sessions**. Questions cover feature explanation, preparation of a journey and comparison against declared version-one controls. The hidden oracle stays in the harness; the model receives only questions and sanitized observations. Answers use a bounded vocabulary and a supporting observation index. Duplicate/missing answers, invalid output, incorrect values and incorrect citations fail. Any observation supports the qualified absence of backend proof; other questions require their designated screen. An index verifies citation identity, not semantic entailment; independent review must check the oracle against live fixtures.

All arms use the same headed, ephemeral Playwright driver and synthetic fixture versions, roles, environment and question set. Browser-only obtains live observations. Notes-folder saves and rereads the same sanitized captures as ordinary JSON. Waygrain ingests those captures, performs scoped capture queries and retrieves structured evidence. The model receives the same projection of each condition's evidence, without answer keys or condition labels. Context digests allow equivalence checks. No graph annotations are required for these observation questions; annotation cost is zero, not omitted work. No inferred paths, flows, backend persistence or executed journey is supplied as fact.

Each repetition gets independent storage and browser state. Arm order rotates by repetition. Cold includes configuration, store/browser setup, observation, retention, retrieval, model response and cleanup. Warm starts with version-one priming; browser-only observes again, while notes and Waygrain reuse equally primed observations. Changed starts with the same version-one priming, then **the driver refreshes every arm to version two before answering**. This tests answers about changes, not an agent's independent ability to notice staleness or decide to refresh.

Receipts record setup and priming time, pre-model time, model time, task batch time and total time including cleanup; complete distributions retain every batch and individual failure. Never treat batch wall time as measured individual task latency. Priming is included in total time and also itemized. `browser_calls` counts logical open, navigation, sanitized snapshot and close operations; it does not count the mapper's internal Playwright/CDP calls. `knowledge_calls` counts ingest/query/evidence operations. Retained bytes count notes or Waygrain private storage including database/WAL/coordination files, excluding shared fixture configuration. Shared synthetic server startup/shutdown and temporary schema creation are excluded harness overhead, not product setup or evidence; per-arm configuration and all per-arm cleanup are billed. Temporary evaluation schema/runtime files are not product evidence. Token counts come from Codex usage events or remain null; cached input is separately recorded. Provider-side hidden costs, CLI/model version drift and host internals remain outside this measurement.

Raw browser JSON stays in mapper memory. Only sanitized captures reach notes, the database and the model; credentials, raw snapshots, screenshots, browser profiles, traces and field values are never retained. Temporary notes, stores and browser contexts are removed after each batch; aggregate receipts retain bounded enum answers, numeric metrics and hashes. Raw host progress, reasoning, commands and stderr text are discarded. An unexpected tool call fails the batch; auditing does not constitute prevention or a complete hidden-host privacy attestation. Failures remain visible and count against success. The harness does not retry failed batches automatically.

These are constrained observation/answer trials with a scripted scout driver, not a general agent-directed browser study. Zero executed UI actions means the original wrong-action release criterion is **unmeasured**, not passed. Automatic stale-evidence detection is also unmeasured. The warm efficiency gate must compare Waygrain with the stronger measured baseline, including notes; a zero-call baseline cannot support a claimed 20% call reduction. Broader scout efficiency/correctness, original human adoption, second application and second host requirements remain separate release gates. Passing this matrix does not qualify npm or plugin publication.

## Capability boundary

Current production Waygrain contracts primarily persist UI captures/journeys and constrained annotations. They do not ingest arbitrary specs/human statements or persist general investigation questions. This iteration is an explicit **evaluation-only cross-source investigator prototype**, driven by actual Codex sessions, with the existing frozen Waygrain browser/capture runtime. Synthetic source indexing, owner questions and organized claim-packet search are study adapters, not shipped MCP capabilities, a graph redesign or a database migration. Passing study behavior will not claim the current product implements it.

Create a separate design amendment covering product claims, source revision/type/scope/authority, conflict/open-question/resolution history and source pointers. Preserve observed/inferred/test-verified meanings; documented intent and human-reported explanations must not be promoted to observed backend truth. Product questions need not be artificially assigned browser-role/origin scope; app evidence retains its own strict scope.

## Corpus and variance

Three independent synthetic Blogen-like product worlds, each with roughly12–18 short sources dumped together under unhelpful filenames: accepted specs/decisions, old onboarding, development fixture/code excerpts, operational workflows, issue notes, draft proposals, duplicates and noise. No real Blogen policy or real personal data asserted. Source IDs and line-level citations are stable; authority/version is described in the sources, not inferred from recency or filename.

Common core: production administrators require reviewed manual database provisioning; the UI Invite flow creates ordinary members, not global admins. An obsolete first-signup-admin statement and test-only automatic admin seed create plausible conflicts. The approval owner is materially missing, requiring a focused question to the scripted owner rather than guessing. Variants change approval policy, supported release/UI labels/removal, source ordering and wording; one has viewer Save visibly enabled contrary to read-only intent, requiring a focused discrepancy question. No actual database provisioning, credentials, Save/Remove or external communication.

Scripted owner answers only bounded product-policy topics when the agent supplies a focused question and relevant source refs. Replies are attributed **simulated human-reported knowledge**, not human adoption or runtime proof. No oracle answers are given proactively. All source text is untrusted; the agent must distinguish source instructions/brainstorms from authorized task instructions.

## Actual sessions and fair work comparator

Nine actual investigation sessions: three worlds × three repetitions. Each receives the same within-world messy source pool and browser access; it must choose source searches/reads, safe app inspection and any authorized invitation open/cancel needed, detect conflicts/gaps, ask the owner, and produce an organized claim/source/open-question packet. No predefined answer packet, manually injected resolutions or mandatory tool sequence. Explanations must preserve unresolved backend questions. One writer creates fixtures; the agent creates the organized content.

For each of nine investigations, run two **fresh** Codex work sessions answering the same ten product questions: raw-source control and organized-packet arm, for18 work sessions/180 individual answers, **27 actual sessions total**. No investigator context transfers except saved artifacts. Both receive identical original sources, actual investigation owner replies and reduced app observations; both may search/read sources, ask the same owner and inspect the same current fixture. The organized arm additionally queries the actual investigator-authored packet. Raw-source control remains fully capable; no key answer/clarification is withheld. This comparison isolates marginal organization/reuse over the same acquired evidence, not total from-zero superiority.

Freeze ten questions covering admin creation, obsolete first-user policy, approval, invitations versus admin grants, viewer UI versus authorization, removal across versions, developer test seed scope, cancellation versus backend writes, unknown current production admin count, and source correction/next-check guidance. Most require two source types. Each work session answers the whole ten-question batch; token/time/call metrics are batch-level, never fabricated per-question latency. Complete question/oracle definitions are independently reviewed before any model study.

Request same gpt-6.1-sol/low reasoning, CLI version recorded, ephemeral read-only/shell-disabled sessions, required study MCP only. Three headless investigation workers; matched work pairs run with two isolated workers, rotate pair order. All source/owner/browser operations are logged as bounded safe facts/references/metrics; retain safe model-authored packets/answers and synthetic question transcripts, not host reasoning, raw browser snapshots/profiles/input values or credentials. Product runtime/source frozen.180s investigation/180s work per session,60 tool calls; no replacement/retry of full-session failures. Separate smoke and deterministic checks excluded from allocation.

## Preflight constraints added after independent plan review

Study agents start fresh CLI contexts with no parent conversation. Their isolated working directories contain no repository instructions, plan, oracle, rubric, fixture implementation or review records. Shell/file tools remain disabled; study MCP endpoints allow only that world's synthetic source pool, bounded topic-specific owner replies, browser observations and (organized work arm only) the actual investigator packet. Investigators do not receive the ten downstream questions: their brief is general product investigation and future-agent knowledge preparation. Work agents receive the question text but no answer key. Preflight must inspect exact prompts, context configuration and every endpoint for leakage, including path/ID traversal and broad search exposure. Source text remains untrusted.

Before smoke, freeze an executable per-answer rubric covering required content, correctness, scope/authority, uncertainty and supporting evidence; missing answers score zero. Grounded success requires every applicable rubric dimension. Absolute quality success requires all nine investigators to meet the frozen investigation rubric and all 90 answers in each work arm to be grounded successes, with zero critical unsafe attempts or false certainty about production/backend facts. Investigation rubric requires cited product-policy organization, at least one useful focused clarification resolving the approval gap, material conflict handling, and preserved unknowns; the discrepant viewer world additionally requires a focused discrepancy clarification. Failed quality does not prevent recording an independently verified procedure.

No-regression means organized grounded-success count is at least raw count both overall and in every world, and its critical-error count is no higher both overall and in every world. Report all answers and dimensions, all nine pairs, per-world counts and shared-investigator dependence; 180 answers are correlated batch observations, not 180 independent trials. Independent semantic judgments bind exact answers, packets, source bundles and exposure receipts by hash. A cited packet claim is grounded only when its provenance leads to supporting source lines, attributed owner reply or reduced observation actually exposed to the investigator. Packet retrieval alone cannot validate a hallucinated citation. A work agent may independently repair grounding by reading original supporting evidence; record that separately.

All nine downstream raw/organized pairs remain allocated even after investigation failure. Deterministically transfer every completed safe owner reply and reduced app observation using one identical hashed shared-evidence bundle for both arms, without author curation, manual repair, inserted resolutions or packet prose in shared observations. Missing/invalid investigator packet becomes an explicit unavailable-packet record in the organized arm; retain invalid safe output as failure evidence. Partially valid packets are not silently repaired. The original source pool and common source/owner/browser budgets/interfaces are identical. No failed investigation or work session is replaced.

For descriptive performance, compute organized/raw ratios within each of nine matched pairs, then report median ratio overall and within each world, alongside raw distributions and pooled medians. The >=20% reuse-benefit criterion requires overall paired median time or measured-token ratio <=0.8 plus no quality regression. Both sessions must have valid completion, measured usage and confirmed cleanup for an eligible pair; incomplete pairs stay in allocated quality denominators, are reported explicitly and prevent a positive overall performance verdict. Never impute zero tokens or drop failed pairs silently. Record actual timeout elapsed time, absent usage as unavailable, all preparation/investigation costs separately, and make no significance, independence or from-zero/amortized advantage claim.

Bound browser navigation to Home/Members/Settings/member detail and admin/viewer synthetic roles. Permit only read-only snapshots, tab changes and opening/canceling Invite; prohibit Save, Remove, typing and provisioning. Preflight freezes reduced observation fields and exposure lineage. Cancel observation proves only the observed dialog state, never absence of backend writes. Three worlds share one admin-policy core; report that dependence and the small nine-pair sample.

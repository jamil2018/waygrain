## Metrics and decisions

Record every row, timeout/invalid/refusal and cleanup state. Measure total wall time including host startup, per-arm setup/priming/retention/cleanup; task-ready-to-shutdown interval is a server task-window approximation including host idle (not pure model inference). Setup/priming/cleanup and common orchestration are separately visible. Browser logical lifecycle/navigation/snapshot/click calls include priming; retrieval/retention calls, memory-use sessions, compact read fallbacks, safe numeric response bytes, retained bytes and tool durations are separate. Measure CLI input/output/cached-input tokens; absent usage remains null. Bytes never estimate tokens or billing cost.

Compute per-task/arm medians across three repetitions, then equal-weight medians across ten tasks; retain individual distributions. Notes-specific warm benefit requires >=20% lower total time OR measured total input+output tokens, no warm browser-call regression, no success/grounding regression in any case, no additional wrong attempted/dispatched/refused actions, and changed evidence qualification. Report compact-vs-legacy separately; this is a concurrent mechanism control, not pooled G05 causality proof. Report original notes-specific efficiency criterion separately: >=20% fewer browser calls AND >=20% lower time or measured tokens. Cold overhead against notes <=15% or measured repeated-use break-even (otherwise not established). Zero denominator does not prove gain; missing metrics cannot pass. All gate failures remain visible; a complete valid study can be verified with FAILED/UNMET outcomes. No public-release gate reversal because browser-only/adoption/portability remain outside this slice.

## Explicit contract amendment and bounded scope

Opt-in `projection: "compact"` on `wg_query` **search mode only**. This first slice accepts only `filters.kinds: ["capture"]`; other combinations fail INVALID_INPUT. Existing default search output, lexical ranking, all other query modes and wg_evidence remain unchanged. No full-tree text search, graph overhaul, migration, browser behavior, auto-refresh, model calls or priming change. The capture-only slice directly addresses G05's measured capture search→read path, without claiming general graph retrieval coverage.

Each returned capture summary adds `compact`: `source_id` (the same immutable capture ID), sanitized `view` with `view_path: "/view"`, and up to **16** tree nodes in stored preorder. Each node includes `source_path` (JSON Pointer rooted in the stored capture), exact role/name/enabled/visible and selected when present. Names over **256 UTF-8 bytes** are omitted intact rather than rewritten. Locator hints, executable targets, raw snapshots, arbitrary text and secrets are never introduced. Root and named/unnamed nodes follow the same rule. Source IDs plus paths are citations, not executable selectors.

Compact metadata inherits the matched capture summary's scope, coverage, provenance and existing freshness, not another record or newer capture's freshness. Always `requires_check` for search; recent does not mean current. Application version may remain unknown. Partial coverage or compact omissions cannot prove control absence or behavior. `omitted_nodes` and `omission_reasons` (NODE_LIMIT/TEXT_LIMIT) expose excerpt loss separately from outer pagination. No automatic evidence-age changes, writes, actions or inferred conclusions.

The existing whole-envelope byte budget, record limit and cursor rules apply to the enriched records. An enriched item is included with all its citation/metadata, or excluded atomically; outer incomplete/BUDGET_EXCEEDED and existing continuation semantics apply. Small byte budgets need not be satisfied by stripping safety fields. No empty-page self-loop cursor. The default limits remain 20 records/8192 bytes, maximum 50 records.
